`ollamacmf` is an **experimental, source-only** Ollama fork for locally
imported CMF v2 generative text models. It keeps Ollama's local API and model
store, then runs the model through a separately configured Cortiq subprocess.

It is independent of Ollama, Inc. and is not an official Ollama distribution.
There is no CMF-enabled installer, Docker image, registry transport, or
automatic binary release today.

> [!WARNING]
> The current Cortiq sidecar uses unauthenticated loopback HTTP and has a local
> port bind race. Use it only on a trusted, single-user host. Read the
> [security boundary](/cmf#security-boundary) before using a CMF model.

## What works today

- Local `FROM /absolute/path/to/model.cmf` import for one runnable CMF v2 text
  model.
- `ollama run`, `POST /api/chat`, formatted `POST /api/generate`, and raw
  `POST /api/generate` through the normal local Ollama endpoint.
- A checked-in [canonical lock](https://github.com/infosave2007/ollamacmf/blob/main/cmf.lock.json)
  for reviewed Cortiq runtime inputs and a matching tiny E2E fixture.
- Linux `amd64` adapter E2E in CI; other locked desktop artifacts have narrower
  evidence documented in the [platform table](/cmf#platform-and-runtime-scope).

## Important boundaries

- CMF `pull` and `push` are intentionally unavailable.
- The runtime is a separately configured Cortiq executable; it is not bundled
  in the fork's source build. Operators select and checksum-verify its archive
  against `cmf.lock.json` before use.
- The current manifest advertises completion only. Embeddings, token APIs,
  rendered templates, images, structured output, log probabilities, tool calls,
  and positive thinking requests are not CMF features of this fork.
- The scheduled workflow proposes a reviewed lock candidate PR. It does not
  build, sign, publish, or update an `ollamacmf` release.

## Inherited Ollama material

This repository retains upstream-derived reference files for source history,
but they are intentionally **not** in this fork's documentation navigation.
They do not override the CMF guide's compatibility/security boundaries, and
upstream installation, cloud, Docker, registry, capability, and integration
instructions do not install or enable this adapter.

Use the **CMF** navigation tab for fork-specific instructions. Use the
[upstream Ollama documentation](https://docs.ollama.com) for general upstream
behavior and [this repository's development guide](/development) for source
build prerequisites.
